# Discovery entities

Every entity the bridge advertises, and the state field behind it. Generated by `generate_reference.py` — do not edit by hand.

Home Assistant creates all of these from the discovery configs alone; no YAML is needed. `obj_id` is the suffix of the generated entity ID.

## Tracker

| Entity | Name | Topics |
|---|---|---|
| `location` | Location | `json_attributes_topic` = `xpeng/l1nnsgha0sb000000/location` |

Coordinates are published on `json_attributes_topic`, **not** `state_topic`: Home Assistant's MQTT device tracker accepts only `home` / `not_home` / a zone name there, and coordinates sent to `state_topic` leave the entity showing raw JSON. There is no `state_topic`, so the state is derived from the position against your zones. `gps_accuracy` is deliberately omitted — the car reports none.

## Topics

| Topic | Retained | Payload |
|---|---|---|
| `xpeng/l1nnsgha0sb000000/availability` | yes | `online` / `offline` |
| `xpeng/l1nnsgha0sb000000/<obj_id>` | yes | the value |
| `xpeng/l1nnsgha0sb000000/state` | yes | every field as one JSON object |
| `homeassistant/<component>/xpeng_<vin>\<obj_id>/config` | yes | the discovery config |

The VIN in topics is lower-cased (`l1nnsgha0sb000000`). Deleting an entity is an empty retained payload on its config topic.

Availability is `offline` once the cached state is older than `stale_after_seconds` (default 1800).
